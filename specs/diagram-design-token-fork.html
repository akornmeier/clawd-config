This skill does not live in ~/.claude. skills/diagram-design is a symlink to /Users/tk/code/diagram-design/skills/diagram-design — a separate git repository, currently on main. Every edit in this plan lands in that repo, and any commit belongs there, not in clawd-config. Confirm the branch before editing.

Purpose

Make diagram-design's first-run branding gate actually fire, collapse the colour tokens back to one owner, and fix two references that point at things which do not exist. The skill's craft content is strong and stays; what is broken is bookkeeping that has quietly disabled a documented feature.

Problem

SKILL.md §0 tells the agent to open references/style-guide.md and, if the tokens are still the shipped defaults, pause and ask the user about branding. It names those defaults as paper #faf7f2, ink #1c1917, accent #b5523a. None of those three values appears anywhere in style-guide.md, whose actual defaults are #f5f5f5, #2d3142 and #eb6c36. Line 30 then says: "if the accent value differs from #b5523a, assume custom." It always differs. The gate has never fired.

The same fork explains a second failure. style-guide.md claims sole ownership of colour in two places — line 3 and line 15, "SKILL.md say accent, not a hex" — while SKILL.md inlines 20 hex literals and reproduces four of its blocks verbatim: semantic roles, node-type treatments, typography, and the Google Fonts link. A third skin lurks in style-guide.md line 36, whose inversion rule is keyed to rgba(28, 25, 23, X) — an ink value nothing else uses.

Two named paths resolve to nothing: SKILL.md line 40 quotes .impeccable.md, which exists nowhere in the repository, and line 57 routes quick unicode diagrams to a wiretext skill that is not installed. The description is a third, smaller problem — it lists all thirteen diagram types and the implementation details, but carries no use when clause and no phrasing a user would type, so "diagram this auth flow" has nothing to match against.

Forced context is 507 lines: SKILL.md's 400 plus style-guide.md's 107, which §0 and §5 both compel unconditionally.

Solution

Replace the value comparison with something that cannot rot. A hex sentinel is a duplicated constant by construction — it has to be kept in sync with a file whose whole job is to change. A references/.skin-customized marker file answers the same question by existing or not, needs no read, and cannot disagree with the palette.

Then give the tokens one owner. style-guide.md already claims it; make it true by deleting the four duplicated blocks from SKILL.md §5 and leaving the focal rule plus a pointer. Delete the stale rgba(28, 25, 23, X) inversion rule. Fix the two dangling references — inline the .impeccable.md quote unattributed, and replace the wiretext route with plain instruction. Finally, add a use when clause with real user phrasing and drop the sentences about gates and variants that do not help routing.

Notes

Two audit claims this plan corrects

The health check produced this plan, but two of its numbers did not survive checking, and the plan is scoped to the corrected ones.

ClaimStatusEffect on scope
"40 of 61 bundled files unreferenced" Refuted by the grader itself — the true number is 0. The scanner missed second-hop links from type-*.md and the documented example-<type>.html glob. No reachability work beyond the two genuinely dead paths.
"40 stale example assets need regeneration" (the grader's basis for medium effort) Refuted here. All 44 assets use only #2d3142, #f5f5f5 and #eb6c36 — the real palette — with zero occurrences of the sentinel hexes. Assets are out of scope entirely. Effort drops from medium to small.

The assets being consistent is also the strongest evidence for the diagnosis: everything that renders agrees with style-guide.md. Only the prose in SKILL.md §0 believes in a palette that was never shipped.

Decisions and rejected alternatives

Just correct the sentinel hex to #eb6c36

The one-character-cheaper fix, and rejected. It restores the gate but keeps the mechanism that broke it: a constant in SKILL.md that must track a file whose entire purpose is to be edited by users. The next reskin re-breaks it, silently, in exactly the same way. A marker file cannot drift because it encodes the decision rather than the value.

Move the token tables into SKILL.md and delete style-guide.md

Rejected. It resolves the duplication in the wrong direction — style-guide.md is the file users edit to reskin, so it must stay the editable surface. Folding it into SKILL.md would make every reskin an edit to the skill's own instructions.

Replace the inline SVG hexes in the code examples with var() roles

Deferred, not rejected. Consistent with the direction, but the examples are illustrative markup a reader copies and adapts, and var() without a surrounding :root renders as no fill — a silent failure of exactly the kind this plan is removing. Phase 2 notes them for follow-up if they drift.

Risks

  • The gate becomes annoying. It has effectively never fired, so nobody has experienced it. Once live it asks a branding question on first use in every repo. If that grates, the marker file makes the fix obvious — ship one, or scope it per project.
  • Description over-correction. Adding trigger phrasing risks firing on any mention of "diagram". The revenue-bar-chart check in Phase 3 is the guard; if it over-fires, tighten the not-for clause rather than gutting the triggers.
  • Wrong repository. The most likely mechanical error in this plan is editing ~/.claude/skills/diagram-design as though it were a real directory and committing to clawd-config. It is a symlink; the work belongs in ~/code/diagram-design on main.

Dependencies

None. Markdown edits plus one empty marker file. Every validation command is grep, wc, or a fresh-session behavioural check.
