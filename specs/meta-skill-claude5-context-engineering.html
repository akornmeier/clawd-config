Purpose

Bring ~/.claude/skills/meta-skill in line with Anthropic's Claude 5-generation context engineering, and give it the one thing it has no copy of: the new rules themselves. The skill that teaches Claude how to write skills is currently the worst-behaved skill in the directory — it violates four of the six rules it should be teaching. Rewriting it fixes the instruction and the example at once.

Problem

SKILL.md is 437 lines / 12 KB, and its very first instruction is a Required Reading block pointing at three bundled docs totalling 43 KB. Creating a skill as trivial as "wrap this one bash command" therefore costs roughly 56 KB — about 14k tokens — before a single design decision gets made. That is Anthropic's rule 3 run backwards: upfront information where progressive disclosure belongs.

The rest compounds it. The same material — progressive disclosure, frontmatter requirements, description writing — is stated in SKILL.md and in all three docs, so the model reads three versions of one idea and has to reconcile them (rule 4). Four long worked examples spell out trajectories Claude 5 would pick on its own (rule 2). Steps 7 and 8 prescribe ls -la to confirm a directory exists, head -10 to confirm YAML parses, and a git add / commit / push sequence — procedure the model applies unprompted. And the frontmatter reads name: Create New Skills, which is neither the lowercase-hyphen identifier format nor the meta-skill the directory is actually called.

Nothing in the skill encodes Claude 5 guidance at all: the newest bundled document is the October 2025 Skills launch post. The prior local audit already caught the symptom — meta-skill scored 4.25 with the note "length (437 lines) could benefit from more progressive disclosure" — but diagnosed it as verbosity rather than as a context-engineering defect.

Solution

Apply the same subtraction that already worked on planf3 in this repo (SKILL.md 241 → 72 lines, template extracted, workflows split by load path). meta-skill's SKILL.md becomes a router of at most 90 lines: frontmatter, three lines on what a skill is, a Contracts block holding only the rules that cannot be derived from the files themselves, a routing table with two entries (create / improve), and a file map whose last column is read it when.

Everything else moves behind that column. The new references/context-engineering-claude5.md is the deliverable the request names: the article's six then→now pairs and its context-assembly guidance, rewritten as instructions for someone authoring a SKILL.md rather than as a summary of a blog post. references/skill-review-rubric.md replaces the vague "Test the Skill" step with gradeable criteria — the article's own recommendation that rubrics let a verification agent hold a specific standard. The inline YAML skeleton becomes templates/SKILL.md. The three vendored docs stay exactly as they are but stop being mandatory: they are demoted to one line each in the file map, opened only when a format detail is actually in question.

Notes

The six rules, applied

The article is a subtraction argument — Anthropic removed over 80% of Claude Code's system prompt for advanced models without losing performance. Here is what each pair costs this specific skill.

Then → NowWhat meta-skill does todayChange
Rules → judgment Prescribes ls -la, head -10, chmod +x, and a git push sequence as workflow steps Cut. Contracts keep only what cannot be derived from the files.
Examples → interface design Four long worked examples, ~120 lines, each walking one imaginary skill end to end Cut. A filled-in templates/SKILL.md carries the shape without pinning the trajectory.
Upfront info → progressive disclosure "Required Reading — read these files in order": 43 KB before step 1 Files table with a read it when column. Nothing is mandatory but SKILL.md.
Repetition → single source of truth Progressive disclosure, frontmatter rules, and description advice each stated 3–4 times across SKILL.md and the docs Stated once, in the reference. The docs are sources, not instructions.
Manual memory → auto-memory Not applicable — no CLAUDE.md guidance in this skill No change. Noted in the reference for skills that do touch it.
Simple specs → rich references Three prose documents, no gradeable artifact Adds skill-review-rubric.md — the article's exact recommendation for verification agents.

Decisions and rejected alternatives

Delete docs/ outright

Rejected. They are verbatim upstream copies and the only offline record of the frontmatter contract and the cross-surface limits. The cost was never that they exist — it was that SKILL.md made reading them mandatory. Demotion removes the cost and keeps the artifact.

Condense the three docs into one format.md

Rejected. A hand-condensed copy silently drifts from upstream and nobody can tell when. Verbatim copies with a provenance line can be diffed against the live docs; a paraphrase cannot.

Keep the rubric inside improve-skill.md instead of its own file

Rejected, narrowly. Both routes end by grading — create needs it as a final check, improve needs it as the opening move. Inlining it in one workflow means either duplicating it in the other or making create read a file named for improvement. A shared reference is the single source of truth.

Two workflow files rather than one, or none

Create and improve are genuinely different load paths: create needs the template, improve needs the target skill's own files. Folding both into SKILL.md re-inflates the router — the exact failure being fixed. Folding them into each other loads the template on a route that never fills it.

Directory name

The request says ~/.claude/skills/meta-skills; the directory on disk is skills/meta-skill, singular. This plan targets the singular path — it is the one that exists and the one Claude Code lists. No rename is proposed, since the skill is discovered by directory and a rename would break nothing but gain nothing.

Scope held

Two adjacent things this plan deliberately does not do. It does not re-audit the other local skills, even though the same 56 KB pattern almost certainly appears elsewhere — specs/skill-assessment-local.md is the right place to reopen that. And it does not run /doctor across the skills directory; Phase 3 runs it against the rewritten skill only, as a check on this work rather than as a new program.

Dependencies

None. Every file added or changed is markdown, and every validation command is grep, wc, ls, or awk. Nothing to install.

Amendments

2026-07-25 — Improve route: flaky firing, rubric never read

Phase 3's Scenario B was run four times headlessly against a deliberately broken throwaway skill. Two findings, both left open rather than patched away.

Firing is 2 of 4. On the other two runs the model diagnosed and patched the broken frontmatter directly, without loading meta-skill at all. Adding "this skill never triggers" to the description's trigger list — the phrasing the eval actually uses — did not make it deterministic. A one-line frontmatter repair is inside the model's unaided competence, so the skill is competing with the model doing the job itself. The output was correct either way; this is a tie, not a miss.

The rubric was never opened — 0 of the 3 firing runs read references/skill-review-rubric.md, despite two attempts to make it unskippable: the grade was moved from step 3 to step 2 of workflows/improve-skill.md, and the step was made explicit that the criteria are to be read rather than recalled. On a 45-line target answering a one-line question, a six-dimension grade reads as disproportionate, and the model skips it. The create route is unaffected — Scenario A read the rubric and graded before reporting.

Both are recorded in skills/meta-skill/evals.md with the re-measurement that would settle it: run the improve route against a realistic target (200+ lines, an open-ended "improve this"). If the rubric still goes unread there, the criteria belong inline in the workflow and the separate file should be deleted.

2026-07-25 — /doctor not run

Marked [f]. The claude doctor CLI subcommand checks installation health only; the skill-and-CLAUDE.md rightsizing pass the plan intended is the /doctor slash command, which needs an interactive session and cannot be driven from this build. Worth running by hand against the rewritten skill.

2026-07-25 — Rubric checklist under-enumerates: 6 dimensions listed, 7 shipped

PR review flagged that Phase 1's checklist item for references/skill-review-rubric.md — "Define the dimensions to grade" — names six dimensions (description triggers, forced-context size, progressive disclosure, rule-vs-judgment balance, single source of truth, reachability) and omits a seventh.

The delivered skills/meta-skill/references/skill-review-rubric.md defines seven: the six above plus Scope — "one skill, one capability" — as dimension 7. The rubric file is correct and is the source of truth; the checklist line above is left as-executed rather than rewritten, per this plan's append-only convention. A reader grading a skill should read the rubric file's table, not recount from the Phase 1 checklist.

The same undercount echoes in skills/meta-skill/evals.md ("a six-dimension grade reads as disproportionate") — out of scope for this plan, but worth a look if that file is revisited.
